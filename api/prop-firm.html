02 / PROP FIRM RULES API

Every account event.
A clearer decision.

Evaluate customer-supplied account data against explicit rules. Follow loss limits, track eligibility and retain the history behind each result.

Developer beta. Evaluations cover the data supplied to the engine. They do not certify unobserved market movements or approve payouts.
01

Define the rules

Create a versioned rule set with explicit loss limits, reset time and completion conditions.

02

Connect an account

Start a separate phase ledger with its own balance, currency and pinned rule version.

03

Submit events

Send ordered realized and unrealized P&L updates with retry-safe identifiers.

04

Explain the result

Read remaining loss allowance, eligibility and the associated event history.

Rules with distinct meanings.

RuleBeta behavior
Daily lossCompare equity to an explicit daily floor; configure the reference and reset time.
Maximum lossSupport static and observed-equity trailing floors, including a cap at initial balance.
Profit targetTrack realized net profit; completion requires the other enabled eligibility conditions.
ConsistencyTrack the best day’s share of total net profit as recoverable eligibility, not an immediate permanent failure.
Minimum trading daysCount valid close events using the same trading-day boundary as daily rules.
Audit historyPreserve event identifiers, rule versions, before/after context and the reason for each evaluation.

ACCOUNT STATE MATTERS

Retries should not
rewrite the outcome.

Duplicate events return the original result. Conflicting retries and out-of-order events are rejected rather than silently changing account history.

A known hard-loss breach remains recorded after equity recovers. Missing boundary snapshots prevent a definitive new pass decision.

Payout execution, automated funding, strategy surveillance and native broker connectors are later integrations.
